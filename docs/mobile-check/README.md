# V2 手机适配专项复测

本轮只修改表现层、布局和测试文档。继续在本地 v2-visual 分支工作，没有 Git 提交、推送或发布。game.js 本轮未修改，原有数值、32 回合、事件规则、结局条件和存档键均不变。

## 已确认并修复的问题

1. 原手机顶部按钮高 32px，字号 9～10px。现在分行排版，高度至少 44px，文字 12px。
2. 原首页按钮区与双人立绘容器重叠约 100px。手机首页改为正常文档流，人物区按实际立绘高度伸展，按钮位于人物下方。电脑仍使用原有海报排版。
3. 320px 原主舞台对白与人物下部相交约 91px。手机与短横屏舞台改为“标题 / 人物 / 对白”网格，文字变长不会覆盖双脚。
4. 原属性和部分收益说明字号偏小。手机属性 14px、行动名称 15px、描述和收益代价 12px、剧情正文 15px、选项名称 14px。320px 属性单列；手机人物选择改为带完整缩略立绘的纵向卡片。
5. 原剧情插画使用负 bottom，有裁剪头顶或毕业帽的风险，尤其在短横屏。现在按容器高度放入整个人物，保持图集比例。
6. 关闭动画或系统减少动画时，原增减浮字会停留在数值上方。现在以正常流内的短变化文字显示，不覆盖当前属性；余额区域允许换行。
7. 隐藏页面时，原逻辑暂停人物呼吸，却未暂停独立闭眼帧。现在用只影响样式的页面可见性标记一起暂停。后台切换不写入游戏存档。
8. 弹窗最大高度扣除上下真实安全区；手机登场动画改为轻微缩放淡入，避免向下位移挤出短屏底部。

“通过”的范围：页面 scrollWidth 等于 clientWidth；可见按钮没有内部横/纵向文本裁切，高度至少 44px；人物在对应容器内，宽高比接近图集原比例 4:9（呼吸和轻微旋转时允许细微偏差）；首页按钮不压人物区，主舞台对白不与人物区域相交；背景使用 cover 自适应；弹窗无内部横向溢出，长内容可以纵向滚动。背景按 cover 裁去两侧是正常取景，不代表人物可随背景裁切。

补充检查：

- 740×360、844×390、932×430 横屏：游戏、人物选择、剧情三类界面均无横向溢出，人物在容器内，长弹窗可滚动。
- 320×568 短屏：剧情弹窗与学期总结可滚动，不裁切选项文字。
- 1024px、1366px 桌面回归：无横向溢出，手机专用人物槽隐藏，原海报双人排版保留。
- 页面控制台检查未发现应用 JavaScript 错误。

实际原始测量在 results.json：六宽度 × 五种视图共 30 组，横屏 9 组，额外短屏与总结 2 组。只读测量函数在 tests/mobile-audit.js；它不是自动启动浏览器的测试器，也不修改 DOM 或存档。测量 JSON 是本轮记录，后续修改界面需要重新跑浏览器，不能用旧记录代替新测试。

## 仍需 iPhone / 安卓真机检查

1. Safari、安卓 Chrome 和至少一种常用国产浏览器打开本地 Wi-Fi 预览或后续 HTTPS 页面，竖屏/横屏切换，查看真实字体、图片透明通道和主角脸部。
2. 单指滚动页面及长弹窗；滚动到底选择最后一项，确认不会误触背后的行动按钮。浏览器模拟点击不等于真实触摸验收。
3. iPhone 地址栏/底部工具栏展开收起、刘海/灵动岛/Home 指示条；安卓挖孔屏、全面屏手势区，检查安全区。本次桌面环境中的安全区通常为 0。
4. 暂停到后台 1 分钟后返回，再测试系统清理进程后打开。确认同一回合、事件、角色和余额可恢复；本轮模拟和适配器未覆盖系统杀进程。
5. 开启系统减少动态效果、较大文字及省电模式，检查文字能否阅读、按钮能否完整操作及动画负载。
6. 旧设备、低性能安卓和较旧浏览器测试滚动与素材解码；本轮未测帧率、内存或所有浏览器版本。
7. 主屏幕独立窗口下再检查以上项目。不要为刷新新版而删除网站数据，避免清掉个人存档。

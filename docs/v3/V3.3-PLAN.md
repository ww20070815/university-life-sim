# V3.3 青春故事与人物羁绊实施方案

仅在 v3-development 开发，复用本地 V3.2。保留 V3.1/V3.2 所有备份、工作区、美术和原核心存档；不提交、推送或发布。

## 阶段一：审计与设计

现有架构为普通脚本/UMD，无构建工具：game.js 核心规则 + UI 桥接；npc-data.js 人物；relationships.js 唯一扩展写入口与局次/双锚点/读失败保护；phone-data.js、phone.js、phone-ui.js 负责校园手机；visual.js、audio.js、companion-ui.js 负责原表现层。旧核心规则段有逐字对照测试。

新增 story-data.js（30章原创内容与番外）、story.js（纯逻辑引擎）、story-ui.js（故事中心与阅读器）。用既有扩展键 data.story/schemaVersion=1，同一 runId。人物原 romance/ending 字段保持原值，剧情关系独立保存。手机正文与通知解释新故事 ID，不新增持久存储键。

### 分支与时间

- 友情完整可通：支持、协作、尊重空间等选择积累真实剧情信任，数值高不能跳章。
- 四位成年同学（林/沈/许/顾）可在第三章明确表达兴趣；第四章须关系≥60、有前置与信任、NPC明确同意且没有其他恋人，才确认。程乐与周老师没有恋爱选项。主角外观不参与资格。
- 第五章分别提供普通友情、深厚羁绊及符合配置/前置的恋爱结果；周老师只有指导成长。
- 每大学回合最多处理一段主要故事，原事件/总结优先。推迟后可续读，必要前置不能跳过。按最早学年解锁而不设置过期失效。
- 毕业后允许按顺序回顾补读，零数值奖励，不增加回合；第五章只在原 ending 阶段开放。关系、行动等资格仍需符合，不自动替玩家认识人物。
- 普通选择从不加属性、金钱或回合；可勾选使用当回合关系交流，调用既有 interact。次数不足可取消勾选，剧情本身仍能继续。毕业回顾无数值奖励。

### 状态与保存

story 保存 schemaVersion、runId、当前 active、触发 ID、完成记录/所选选项、关键标记、每回合故事槽位、人物叙事关系/恋爱、番外状态和已领关系奖励。任务/手机原状态不替换。

所有命令经过 relationships.js 的同步和读失败保护；先检查资格，再一次性更新选择与奖励。核心成功写入后才协调新剧情提示，保留原双锚点中断恢复。渲染只读；旧档初始化只在内存补齐，坏档原文隔离。

## 阶段二至七验收

1. 引擎：统一资格、前置、排队、推迟/续读、每回合限制、单次选择和安全存档。
2. 内容：六人五章共30唯一ID，完整正文、选择结果、前章分支回声。
3. 分支：六条友情与深厚路线、四条可选恋爱、拒绝/改为朋友、教师禁止恋爱、单一恋人。
4. 番外：原八结局原样保留，附加人物故事结果；无人物路线照常毕业。
5. 界面：校园/手机/档案入口、当前/待处理/历史/锁定条件、可滚动阅读、原背景与声音、姓名印记及表情资源接口。
6. 测试：实际运行原77组与新增引擎/分支/存档/UI测试；每人友情、可选恋爱、分支回声、刷新和番外。语法、相对路径和 diff 检查。
7. 浏览器/真机：此前来源权限仍被应用保存的拒绝设置拦截，不绕过，不引用旧截图；没有实际测量的布局、控制台和真机结果明确待测。

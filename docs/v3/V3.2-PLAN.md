# V3.2 校园手机开发与验收清单

仅在 v3-development 开发，保留 V3.1 工作区和两份稳定备份；不推送、不发布、不开始 V3.3。核心源码段、存档键和原结局保持不变。

## 实施顺序

1. 审计扩展存储与界面桥接。采用既有人物扩展中的可选 phone 命名空间、schemaVersion=1 和相同 runId，不新增第二套持久存储。
2. 编写六人问候与 12 组对话、24 条校园动态、六类通知、六类真实行为任务。
3. 实现纯逻辑手机模块：资格、幂等触发、回复/已读、任务派生和格式校验。
4. 接入现有关系 store：统一写入口、同回合奖励预算、过期页保护、双锚点中断恢复。旧档只读初始化，不在渲染时写盘。
5. 制作手机首页/聊天/动态/通知/任务，复用姓名印记，不伪造 NPC 立绘。
6. 完成移动布局与键盘返回、未读提示及真实新消息音效。
7. 执行原有 51 组和新增测试，浏览器模拟六种手机宽度，记录真机待测项，另存稳定快照。

## 验收门槛

当前：功能与自动逻辑/UI 回调验收完成，74 组通过。浏览器访问权限被拒绝，六宽度视觉与真机检查仍未完成，详见 V3.2-DELIVERY.md。

- 六人聊天按相识和真实行动解锁；每人问候、两组各三方向，选择记录和后续消息可恢复。
- 普通回复免费；关系回复调用 V3.1 同一预算，同题不能重复答，跨页面和刷新不能重复领奖。
- 动态按学期解锁，不在大一显示毕业；已读不产生属性收益。
- 通知六分类、筛选、详情和跳转；事件 ID 幂等，学期/学年更新正确。
- 六类任务均由真实核心行为、关系或回复推进，无领取按钮、无自动属性奖励。
- 旧无 phone 数据兼容、坏手机数据隔离、runId 校验、换角色保留、新游戏重置、存储禁用安全。
- 原核心规则源码不变；32 回合、18 事件、八结局全回归。
- 320/360/375/390/412/430px、横屏、平板及电脑检查，真机结果另列，不能虚报。
